# kasm_credentials

**Fully qualified name:** `pepesan.kasm.kasm_credentials` (collection [`pepesan.kasm`](https://galaxy.ansible.com/ui/repo/published/pepesan/kasm/))

Generates random, per-host Kasm admin/user passwords (persisted on the
control node so repeated runs reuse them) and records this host's credentials
in a shared access CSV named after the inventory (`access-data-<inventory>.csv`,
e.g. `-i inventory-my-course` → `access-data-inventory-my-course.csv`), one
row per node. It is used by [`kasm`](../kasm/README.md) and reads the same
`student` password file generated by [`student`](../student/README.md).

The CSV columns, in order, are `kasm_url`, `ip`, `student_user`,
`student_password`, `kasm_admin_user`, `kasm_admin_password`,
`kasm_normal_user`, `kasm_normal_user_password`. Rows are sorted in ascending
full Kasm URL order. `ip` comes from `ansible_host`.
The CSV directory is created with mode `0700`, and each CSV file is mode
`0600`; neither exposes credentials to other local users.
Not covered by any Galaxy role or collection — this is Kasm-specific
bookkeeping with no equivalent upstream.

## Where to find each password

All of this lives on the machine running Ansible (never in the repository):

| Password | Where | Set a fixed one with |
|---|---|---|
| Linux user `student` | access CSV (`student_user`, `student_password`) and `.credentials/[<project>-]<host>-<student_name>.pass` | `-e student_password_plain=...` |
| Kasm `admin@kasm.local` | access CSV (`kasm_admin_user`, `kasm_admin_password`) and `.credentials/[<project>-]<host>-kasm-admin.pass` | `-e kasm_admin_password=...` |
| Kasm built-in `user@kasm.local` | access CSV (`kasm_normal_user`, `kasm_normal_user_password`) and `.credentials/[<project>-]<host>-kasm-user.pass` | `-e kasm_default_user_password=...` |
| Kasm users created with [`kasm_user`](../kasm_user/README.md) | `.credentials/[<project>-]<host>-kasm-user-<username>.pass` only (the CSV has one row per host) | `-e kasm_user_password=...` |

Any of them can be passed as a parameter; if not, a random one is generated once and reused on later runs. The CSV
records the value actually in use, including a fixed one.

## Variables

| Variable | Default | Purpose |
|---|---|---|
| `kasm_credentials_dir` | `<current directory>/.credentials` | Where generated password files live (keep in sync with `student_credentials_dir`) |
| `kasm_admin_password` / `kasm_default_user_password` | random, persisted | Override with `-e` to set fixed passwords |
| `kasm_credentials_admin_user` / `_user_user` | `admin@kasm.local` / `user@kasm.local` | Usernames recorded in the CSV |
| `kasm_credentials_student_name` | `{{ student_name | default("student") }}` | Name of the Linux user created by [`student`](../student/README.md); follows `student_name` automatically so the right password file is read |
| `kasm_credentials_csv_prefix` | `access-data` | Prefix of the CSV file name (letters, digits, `.`, `_`, `-`). The repository `.gitignore` only covers `access-data-*` (and the old `datos-acceso-*`): add your pattern if you change it |
| `kasm_credentials_csv_name` | `access-data-<project|inventory>.csv` | Exact CSV file name, derived from `kasm_training_project` (or inventory file). Set to `""` to fall back to the day-of-run naming. Plain `*.csv` name |
| `kasm_training_project` | `""` | Course/cohort prefix for generated passwords and access CSV (`access-data-<project>.csv`) |
| `kasm_credentials_csv_dir` | `<current directory>` | Where the CSV is written (the directory `ansible-playbook` is run from, not the folder of the playbook) |

Requires `kasm_domain` to be set by the caller (normally provided by
`kasm`).

Rows are sorted in ascending full Kasm URL order, then by IP and inventory
name.

## Idempotency

`files/update_credentials_csv.py` identifies a node by IP or inventory name,
migrates legacy columns, removes duplicate rows and sorts by Kasm URL. It
rewrites the CSV only when the canonical rows or column schema change and
prints `CHANGED ...`; otherwise it prints `OK ... already up to date`. The
Ansible task's `changed_when` reads that marker.

## Concurrency

The CSV update is safe for parallel multi-host runs: `files/update_credentials_csv.py`
uses a blocking `flock` around the read-modify-write cycle and writes
atomically (temp file + `os.replace`), so concurrent hosts delegating to the
same control node never corrupt the file or lose a row.

## Example


Generate the passwords and record them in the access CSV (this is what the install playbook does before `kasm`):

```yaml
- hosts: kasm
  roles:
    - role: pepesan.kasm.kasm_credentials
      vars:
        node_name: kasmdemo
        kasm_domain: "{{ node_name }}.kasm.example.com"   # the address written in the CSV
```

Fix some passwords yourself and name the CSV after the course, so deployments for different courses do not share a file:

```yaml
- hosts: kasm
  roles:
    - role: pepesan.kasm.kasm_credentials
      vars:
        kasm_domain: "{{ node_name }}.example.com"
        kasm_admin_password: "{{ vault_kasm_admin_password }}"
        kasm_credentials_csv_name: "access-data-course-2026.csv"
```

Look at the result without printing any password:

```bash
head -1 access-data-*.csv                 # the columns
cut -d, -f1-3 access-data-*.csv           # Kasm URL, IP and inventory name
ls -l .credentials/                       # one file per password, mode 600
```
